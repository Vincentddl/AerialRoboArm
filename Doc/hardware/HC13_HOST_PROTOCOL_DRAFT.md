# HC13 上位机接口格式建议稿 V1

> 已由 [完整上位机通信协议 V1](./HC13_HOST_PROTOCOL_V1.md) 替代。以下保留为历史建议稿；状态字段和模式规则以新文档为准。

状态：设计建议，尚未在当前采集固件或截图上位机中实现。现有 RTT 采集格式继续保留。

## 传输约定

- ASCII 文本，逗号分隔，一帧一行，以 LF（`\n`）结束；接收端兼容 CRLF。
- 每行最长 160 字节（不含行尾）。只在收到完整行后解析，支持一帧分多次接收或一次收到多帧。
- 项目目标配置为 230400、8N1；应先核对两端 HC13 的实际串口配置，再统一 MCU 与电脑端。截图的 115200 不能当作模块实际配置。
- 数值使用十进制整数。禁止空字段、无效数字或越界参数；不要把错误内容解析成零。
- MCU 时间为 uint32 毫秒计时，重启归零；绘图使用 MCU 时间，电脑接收时间单独保存。重启时开启新会话，时间回绕按 uint32 差值处理。
- 本格式中的加速度是传感器数据，包含重力；不是已做重力补偿的线加速度。

## 最小传感器帧：MCU 到电脑

```text
ACC,<seq>,<t_ms>,<ax_mg>,<ay_mg>,<az_mg>
```

示例：

```text
ACC,128,152340,85,-20,998
```

| 字段 | 类型/单位 | 含义 |
| --- | --- | --- |
| seq | uint32 | 本会话 ACC 无线上报帧序号，每上报一次加一，不使用全部 IMU 包的混合序号 |
| t_ms | uint32，ms | 该加速度样本在 MCU 被接收的时间，不是无线发送时间或电脑接收时间 |
| ax_mg / ay_mg / az_mg | int32，mg | 有符号三轴加速度，1000 mg = 1 g |

上述示例绘图为 X=0.085 g、Y=−0.020 g、Z=0.998 g。

传感器内部继续约200 Hz输出；无线界面首先按20 Hz上报最新样本。这里是取最新样本的降频显示，不宣称抗混叠滤波后的测量结果。完整200 Hz实验数据继续通过RTT保存。

## 状态帧：MCU 到电脑

```text
STATE,<t_ms>,<mode>,<hx8_online>,<imu_online>,<pos_mdeg>,<target_mdeg>,<voltage_mv>,<imu_hz>,<record_on>
```

示例：

```text
STATE,152340,MANUAL,1,1,-29700,-30000,11980,200,1
```

- 模式：`MANUAL`、`VISION_DEMO`、`VISION_PICK`。
- hx8_online / imu_online / record_on：0或1；record_on表示完整实验记录开关，不等同于无线帧发送开关。
- pos_mdeg / target_mdeg：有符号编码器角度，1000=1°，例如−29700为−29.7°。
- voltage_mv：HX8反馈供电电压，11980为11.98 V。
- imu_hz：MCU实际测得的ACC有效输出率；不能用20 Hz无线上报率代替。
- hx8_online=0时，位置和电压字段填`NA`；imu_online=0时ACC停发，imu_hz填0。上位机显示未知/离线，不能用旧值或0冒充有效测量。
- 状态帧初期1 Hz；关键模式回复立即发送。在线判断由MCU根据新鲜度得出；电脑也应对整条链路设置超时。
- 这个最小状态帧未定义“折叠完成”等实际形态，上位机仍显示未知，不能把已请求的形态当作已达到。

## 模式请求与确认

电脑发送：

```text
MODE,42,VISION_PICK
```

MCU成功切换后回复：

```text
ACK,42,MODE,VISION_PICK
```

不能切换时回复：

```text
ERR,42,BUSY
```

- 42为请求序号；请求序号只用于控制请求，不能与ACC帧序号混用。
- ACK必须在切换实际完成、传感器无线发送已停止后回复；只收到字节不能回复成功。
- 进入任一视觉模式时，取消尚未发送的ACC帧、使旧视觉目标失效，再接受新视觉帧。必要的确认、错误与低频状态回复保留。
- 动作进行中先拒绝切换（BUSY），不自动截断当前实验或执行另一套运动流程。
- 同一个请求序号的重复请求只重发原结果，不重复执行动作；同序号不同内容报冲突。
- 上位机收到对应ACK后才开始视觉目标下发；超时不能默认为成功。
- 返回MANUAL后恢复传感器上报；实验记录开关独立管理，不能因切模式静默改变记录状态。

## 视觉目标：沿用现有解析格式

```text
V,<angle_deg>,<speed_deg_s>,<confidence>
```

示例：

```text
V,-60,500,95
```

表示目标−60°、速度500°/s、置信度95%。现有驱动也接受第五字段stable_frames，但其是否控制夹爪由最终选定的抓取策略决定，不能重新引入已经取消的自动闭合行为。

视觉目标中的角度仍是整数度，不是STATE的毫度。沿用这一区别是为了兼容当前视觉程序。不能将两种字段的单位混用。

## 其他数据的扩展

若上位机需要角速度或姿态，使用独立类型：

```text
GYRO,<seq>,<t_ms>,<gx_mdps>,<gy_mdps>,<gz_mdps>
ATT,<seq>,<t_ms>,<roll_mdeg>,<pitch_mdeg>,<yaw_mdeg>
```

GYRO单位为0.001°/s，ATT单位为0.001°；每种类型各自维护序号及样本接收时间。这些帧与ACC一样，在视觉模式下停止无线发送。初期只实现界面必需的ACC、STATE和模式确认，不默认叠加所有数据流。

## 控制接入边界

手动出臂、速度设置、回零、形态切换及停止命令尚需单独确定；不能把GUI滑块位置百分比直接解释成°/s，也不能把“出臂30°”直接当作编码器+30°。必须先确认界面含义与实际机构的映射。

当前RTT中的g/v/r/h/x命令不能因本建议稿而宣称已能从HC13接收。接入时需要明确选用同一解析入口或新的请求协议，保留现有健康检查、角度限位和到位判断。

验证阶段应先做静态无运动的数据上报和模式确认测试，再验证视觉控制延迟、无线丢帧与完整200 Hz记录是否互不影响。

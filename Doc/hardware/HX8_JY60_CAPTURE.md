# HX8 出臂与机体 JY60 响应同步采集

JY61P 200Hz 替换方案见 [JY61P_CAPTURE.md](./JY61P_CAPTURE.md)，使用独立的 JY61P 烧录脚本。本文保留旧 JY60 20Hz 操作说明。

## 1. 链路与时刻定义

- JY60 保留在原 ELRS 插座，USART1/PB7 接收，9600 baud。接收机必须断开。
- HX8 保留在 USART2/PA2、PA3，经 UC-01，115200 baud；ID=0。
- DAPLink/SWD + RTT 同时传数据和命令：**9090 / RTT 0 给 VOFA 控制台，9091 / RTT 1 给电脑采集脚本**。无需另接一个 USB-TTL 或使用 COM4。
- 两类传感数据和事件由同一 MCU 毫秒计数器打时间戳。START 的 `t_ms` 是完成总线间隔等待后、调用 UART 发出控制帧前的时刻，`tx_end_ms` 是 UART 发送完成后；不依赖电脑收到日志的时间。
- JY60 的 `t_ms` 是 MCU 完成解析该包的时刻，并非 IMU 内部物理采样时刻。DMA 排队、UART 字节传输、总线操作以及 IMU 内部滤波仍会带来延迟，不能宣称硬件级同步或零延迟。当前 20 Hz 输出不能通过多打印日志提高采样率。

默认以现有 VOFA 手动输入为触发：先开脚本，等它提示 READY，再由 VOFA 发送 `g <角度>`。另一种显式 `--target` 方式可由脚本发一次命令。只有一方负责发角度，不要同时操作两处。

## 2. 实验固件与安全边界

这是独立构建 `HX8_JY60_CAPTURE=ON`，不启用完整机械臂状态机、ELRS、HC13、PWM 夹爪和自动回零。启动只读传感器，**收到有效 g 命令前不发位置运动指令**。

运动准入需 HX8 反馈在 9.0～12.6 V、无 BIT1～7 保护、角度在 −90°～85°范围，且有约 300 ms 稳定反馈；同时 JY60 姿态和角速度数据须新鲜。实验中失去反馈、保护状态或超过 10 s 运动超时会发出停止保持指令并结束本轮。通信已经中断时无法保证停止指令到达。

不提供自动位置修正，不把机体 IMU 的姿态当作舵机角度反馈。`x` 为实验固件的停止保持指令；与正常固件中停止释放保持力矩的行为有区别。每轮运动/后录期间拒绝第二个 g 命令，防止覆盖实验。

默认速度 500°/s（断电重启后仍为 500°/s），加减速各 100 ms，完成后录制 1000 ms。这些是命令约束，不是实测速度。当前软件只允许 1～500°/s、20～2000 ms 加减速设置；10 s 超时意味着极慢的大角度运动可能被中止。`v` 指令只修改本次运行的速度；采集脚本显式发起运动时默认也使用 500°/s。

## 3. 烧录和启动

PowerShell 在 MCU 项目根目录运行：

```powershell
.\tools\flash_hx8_jy60_capture.bat
```

脚本编译 `cmake-build-hx8-jy60-capture`，烧录校验后加载 `daplink_rtt_capture.cfg`，暴露 9090 与 9091。普通 `daplink_rtt_attach.cfg` 只开 9090，不能代替本采集配置。保持 RTT 服务运行。

VOFA 连接 TCP 127.0.0.1:9090，文本换行 `\n`，看到 `[CAP] READY ... ready=1` 后可以接受实验命令。

## 4. 现有 VOFA 操作方式（推荐）

1. 支撑好测试台架，传感器刚性固定在研究机体姿态的基座上，保持机械臂运动范围清空。
2. 先在终端运行 Python 3.9+（仅标准库，无额外依赖）：

```powershell
python .\tools\capture_hx8_jy60.py
```

3. 等脚本出现 `READY: send one g <angle> in VOFA now.`，再由 VOFA 发送例如 `g -20`。示例是实际运动命令，应按当前机构位置选择目标。
4. MCU 成功发送角度帧后产生 START，脚本自动保存该轮；无需人工按保存。脚本默认保留发令前 200 ms 的缓存作为基线。
5. HX8 反馈进入目标 ±1°，连续五次新反馈相邻变化不超过 0.3°后产生 ARRIVED（反馈约 50 ms/次，因此到位判定还包含约 200～250 ms 确认时间）。不使用 JY60 判断舵机到位。若稳定在目标 1°以外，则可能在 10 s 后超时；该轮保留数据但不能标为正常到位。
6. 再保存 1 s 机体响应，产生 END；脚本自动结束并保存本轮，**继续监听下一条 g 命令，不退出进程、不重连数据端口**。每轮单独新建 `move_001_...`、`move_002_...` 文件夹，避免连续操作只记录第一轮。机体在出臂后仍可能振荡，尾段有研究价值。

默认持续待命，空闲不超时。`--wait-seconds 600` 可设置空闲 10 分钟后退出；`--once` 恢复只记录一轮然后退出的方式。`--target` 始终是显式下发并记录一轮，不会自动重复运动。

每条解析正确的 `g` 都会产生独立 `REQUEST`，即使目标与上次相同也重新记录。接受后关联到对应运动文件夹；未就绪、越界或忙碌时也创建 `request_..._rejected` 文件夹，保存目标、时间和拒绝原因，标记 `accepted=false/complete=false`。拒绝记录不包含虚构的运动样本，不能当作成功采集。上一轮未结束时仍不允许覆盖运动；应等 `ready=1` 再发下一条。

VOFA 命令：

| 命令 | 含义 |
| --- | --- |
| `g -20` | 目标 −20°，触发一轮 |
| `v 220` | 后续试验速度 220°/s |
| `a 100` | 后续试验加减速各 100 ms |
| `w 0` | 下一轮到位确认后立即结束，不留后录；默认 `w 1000` |
| `x` | 请求停止保持，当前记录标为 operator_stop |
| `?` | 查看命令 |

输入支持 ASCII 空格/Tab、首尾空白，以及常见 UTF-8 全角空格、全角数字和负号。建议直接使用 `g -20` 这样的 ASCII 文本。超过 1 秒未完成的残留行会丢弃；非法输入显示 `REJECT reason=bad_input ... hex=...`，便于检查上位机实际发送的字节。该兼容性由 `tools/test_capture_command.ps1` 验证；范围、就绪和故障门禁保持不变。

## 5. 脚本负责发令的可选方式

下面会实际下发 −20°，不是仅读取。先确认机械运动条件：

```powershell
python .\tools\capture_hx8_jy60.py --target -20 --speed 220 --ramp-ms 100 --post-ms 1000
```

脚本等设备 READY 且收集到预备数据后才向 9090 发送配置和 g。**省略 `--target` 时不发送运动命令**，`--speed/--ramp-ms/--post-ms` 仅在显式发令方式中用于配置固件；VOFA 方式请通过 `v/a/w` 设置。

## 6. 输出和完整性

默认连续方式保存在 `outputs/hx8_jy60_capture/<时间>/move_<序号>_.../`，每轮包含：

- `samples.csv`：逐条有效观测，包含流类型、序号、MCU 时间和相对发令时间；ACC 单位 g，GYRO 为 °/s，ANGLE 为 °，HX8 含角度、电压、电流、状态。
- `raw.jsonl`：原始事件和数据，额外保留电脑接收时间以便排查传输延迟。
- `metadata.json`：START/ARRIVED相关原始事件见 raw，END、指令参数、缺包统计和成功标志。`complete=true` 需要正常 END、无记录错误、无 RTT 数据丢弃、无 IMU 校验错误和采集期间序号缺口。

连续方式的会话根目录还保存 `session_events.jsonl`，退出时生成 `session_metadata.json`。`--once` 和 `--target` 为兼容保留原单轮目录布局。已完成的单轮文件不会因后续测试失败而覆盖。

`samples.csv` 采用长表，一种数据包一行。加速度、角速度和姿态包分别带时间戳，**没有把不同时刻的数据假装成同一时刻的采样**。发令前基线时间为负。第 8～9 字节保留为 tail_raw，不宣称已验证温度。

脚本遇到超时、连接断开或 Ctrl+C 会保存已有文件并标记 incomplete；若本轮已启动但没有 END，会尝试通过 9090 发送 x。设备复位会使该轮无效。`complete=true` 只代表协议和记录流程完整，不代表数据已满足动态测量精度或机械安全验收。

## 7. 验证与恢复

`python -m unittest discover -s tests -p test_capture_hx8_jy60.py` 使用模拟数据流验证自动启停、预记录、毫秒时钟回绕、缺包/校验错误拒绝、显式发令、连续两轮不重连以及第二轮失败仍保存数据，不会连接实物或转动舵机。

2026-10-19 已实机验证 USART1 JY60 和 USART2 HX8 同时回包。单轮 −20°测试完整保存，START 到 ARRIVED 395 ms，加 1 s 后录后 END 为 1395 ms；含预记录共有 126 行（ACC 31、GYRO 32、ANGLE 32、HX8 31），无序号缺口、RTT 丢弃或 IMU 校验错误。随后 −60°因旧脚本已结束而未形成数据文件，不能认定该轮已采集。连续待命改版已通过离线双轮测试，下一轮需按新流程实机确认。

恢复仅读 JY60：`.\tools\flash_jy60_demo.bat`；恢复完整机械臂程序：`.\tools\flash_and_rtt.bat`。这些会替换板上程序。原完整固件的 USART1 仍为 ELRS 配置；不要直接把连接着 JY60 的接口当成 ELRS 在线输入。

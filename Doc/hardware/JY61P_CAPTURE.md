# JY61P 200 Hz：复用原 ELRS USART1

## 接线

仅用于独立 HX8 联合采集模式，拔掉 ELRS。主板原接口 1=GND、2=5V、3=PB7/USART1_RX、4=PB6/USART1_TX。

| 主板 | JY61P |
|---|---|
| GND | GND |
| 5V | VCC |
| PB7 / RX | TX |
| PB6 / TX | RX |

按丝印接线，不能直接假定旧模块插头的物理排列相同。使用 TTL 模块。HX8 仍通过 USART2 PA2/PA3、115200 波特率连接 UC-01。

## 启动配置

新模式 `HX8_JY60_CAPTURE=ON`、`JY61P_CAPTURE=ON`，文件和采集脚本的历史 JY60 名称保留以兼容旧记录。正常完整机械臂程序的 ELRS 配置不变。旧 JY60 联合模式明确设置 `JY61P_CAPTURE=OFF`，保持 9600。

程序等待传感器启动 1.2 秒，然后依次在 115200、9600、230400、57600、38400、19200、4800 波特率寻找至少三个校验正确的数据包。每档等待 700ms；输出被关闭或设为极低频率的模块可能无法被发现，须先在厂家上位机恢复默认 10Hz 输出。识别过程不证明硬件型号，务必接 JY61P。

识别成功后发送官方 WIT 配置指令：

| 指令 | 用途 |
|---|---|
| `FF AA 69 88 B5` | 解锁 |
| `FF AA 04 06 00` | 改为 115200，然后 MCU 切到相同波特率 |
| `FF AA 69 88 B5` | 再次解锁 |
| `FF AA 02 0E 00` | 仅输出加速度、角速度、角度 |
| `FF AA 03 0B 00` | 输出 200Hz |
| `FF AA 1F 02 00` | 带宽 98Hz，用于观察动态过程；会比低带宽更嘈杂 |

解锁后按官方说明等待 200ms，再发送后续写指令。不执行校准、角度置零、恢复出厂或 EEPROM 保存。每次 MCU 重启会重新配置；若模块稍后才供电，供电后重新启动 MCU。`IMU_CONFIG sent=1` 仅表示配置指令成功发送，不是传感器确认。只有收到数据后才统计实测速率。

## 速率和记录

- USART1 为 115200 8N1，1024 字节循环 DMA 缓冲。三包/周期、每包 11 字节，200Hz 合计 6600 字节/秒；一圈缓冲约 155ms，主循环必须持续读取。
- 沿用 0x55/0x51、0x52、0x53 的 11 字节校验协议，换算系数分别为 16g、2000°/s、180°。保留末尾原始两字节，不将所有包末尾误读成温度。
- RTT1 缓冲增至 8192 字节，约可缓冲百毫秒量级的文本输出；不是无限存储。RTT0 仅状态，RTT1 保存完整采样。无主机读取时允许丢弃并累计 drops；每轮单独统计丢弃，不能把有丢弃的记录称为完整。
- 每秒输出 `[CAP] IMU_RATE acc_hz=200 gyro_hz=200 angle_hz=200 rate_ok=1 ...`。只有三类均约 180～220Hz 且新鲜（小于 50ms），才允许发起动作；低速连接不能冒充 200Hz。实测吞吐和时延仍须硬件验证。
- HX8 反馈仍为 20Hz，提升 IMU 频率不等于提升 HX8 反馈频率。时间戳仍是 MCU 接收解析时间，不是 IMU 内部同步采样时间。
- JY61P 原始传输使用紧凑文本 `[I] seq,t_ms,type,x,y,z,tail`，避免 200Hz 下冗长键名占满 RTT 带宽；所有数值均保留。采集脚本兼容此格式和旧 `[IMU]` 格式，输出 CSV 列和单位不变。采集 RTT 使用 20ms 轮询、1MHz SWD；2ms 轮询在持续测试中出现 DAPLink USB I/O 错误，已撤回。短时无丢包不证明长期稳定。
- 每轮 END 新增 `uart_recoveries`；发生 DMA 接收恢复的记录会被 PC 脚本标为不完整。校验错误、RTT 丢包和序号缺口也继续检查。
- HX8 默认 500°/s，加减速各 100ms；启动不回零、不自动出臂，仍由 VOFA `g <角度>` 触发单独记录。

## 编译、烧录、采集

### 按需记录开关（2026-10-27）

每次上电默认关闭动作数据记录：`mode=MANUAL_HX8 record=0`。在 VOFA/RTT 9090 发送 `r 1` 开启，等待 `record=1 ready=1` 后发送 `g <角度>`，每次单独保存。发送 `r 0` 关闭，后续 `g` 仅作为 HX8 手动调试，不创建动作 CSV。实时状态和连接检查继续运行，保留少量状态事件日志，IMU 只在 RAM 内保留短基线缓存。

录制或手动动作执行期间发送 `r 0/1`，将打印 `RECORD_SWITCH ... after_current_move=1`，当前动作按原模式完成并保存，然后应用开关，不截断当前文件。窗口显示 `RECORD=OFF VIEW_ONLY` 或 `RECORD=ON WAITING_FOR_G/RECORDING`。`m` 保留为同一模式开关的快捷切换，但建议使用明确的 `r 1/r 0`。

`h` 的回零恢复独立于此开关，始终不是正式实验记录。`--target` 是显式发起一次采集的脚本用法，会在必要时先开启记录并等待新的采集就绪状态，再发角度；普通后台监测脚本不会自动开启记录或发运动命令。

### HX8 单独手动调试

JY61P 暂时没有有效数据、只需调角度时，在 VOFA/RTT 9090 输入 `m` 进入 `MANUAL_HX8`。等待 `[CAP] READY mode=MANUAL_HX8 ready=1 hx8=1` 后使用 `g <角度>`，例如 `g 0`。只依赖 HX8 的供电、状态、稳定反馈和 −90°～+85° 硬限位，保持到位/超时及停止保持保护。`m` 再按一次返回 `CAPTURE`，正式采集仍需 JY61P 约 200Hz 的新鲜数据。进入任何模式后都不会自动移动。

手动动作打印 `MANUAL_START`、`MANUAL_ARRIVED`、`MANUAL_END`，不生成实验 `START/END`，电脑采集脚本也不会给手动动作生成样本 CSV 或 `COMPLETE=True`。这种模式用于角度调试，不用于有无配重的 IMU 采集。

显式发送 `h` 可执行一次编码器零位恢复：固定目标 0°、30°/s、加减速各 500ms，不重新定义舵机零点。此专用入口允许从编码器 ±180°范围内、稳定至少 300ms 的健康反馈起步，路径仅限起点与 0°之间（加 2°反馈裕量），保留电压、故障、反馈超时、10秒运动超时和 `x` 停止保持。普通 `g` 的 −90°～85°范围不变。回零为显式动作，不在启动时自动执行；打印 `RECOVERY_START/ARRIVED/END`，不当作正式 IMU 实验记录。到位需连续五个新反馈满足误差 ≤0.5°及相邻变化 ≤0.3°。

运行 `tools/flash_hx8_jy61p_capture.bat` 编译独立目录 `cmake-build-hx8-jy61p-capture`、烧录校验并打开 RTT。旧 JY60 使用 `tools/flash_hx8_jy60_capture.bat`。

运行 `python tools/capture_hx8_jy60.py` 连续记录（脚本同时兼容 JY60/JY61P）。VOFA 连接 TCP `127.0.0.1:9090`，采集使用 `9091`。见到 `rate_ok=1` 和 `ready=1` 后才测试运动。新固件在实机验证前，不能声称已经实现无丢包 200Hz。

### 可见采集状态

负载对比实验按动作分段记录，保留运动前 200ms、运动过程及到位后 1 秒。两次动作之间等待装置近似静止，但不持续录制整段等待；有无配重应使用相同角度、速度、加减速和传感器安装方式。

运行 `powershell -NoExit -File tools/start_capture_monitor.ps1` 打开并保留状态窗口。同一时刻只开一个采集脚本。

- 每两秒 `LIVE 时间 READY=1 HX8=1 IMU=1 Hz=... NEW_DROPS=0 WAITING`：新数据仍在到达。`NEW_DROPS` 是两次显示之间的新增 RTT 丢弃，不是启动前累计值。
- `RECORDING: ...`：电脑已收到 START，正在写入此轮文件。
- `SAVED: ... COMPLETE: True`：文件关闭并保存，END 正常且未检测到采集丢弃、校验错误、序号缺口、UART 接收恢复。
- `COMPLETE: False`：文件已保存但本轮不合格，查看超时、丢包等原因。
- 连续 5 秒没有有效遥测，即使 TCP 仍连接也报 `STREAM STALE` 并退出；窗口保留错误提示。活动试次保存为不完整并尝试发送停止保持，但失联时不能保证停止命令到达。

VOFA 自身的蓝色发送回显不证明 MCU 收到，更不能证明电脑采集成功。应同时看此窗口的 `SAVED ... COMPLETE: True`。这能识别已知故障，不能保证硬件永不掉线。

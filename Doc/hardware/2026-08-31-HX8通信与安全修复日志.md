# 2026-08-31 HX8通信与安全修复日志

## 1. 修复背景

真机日志中出现以下现象：

- ELRS链路仍在线，但HX8偶发`rd=5`回包超时；
- 拨动摇杆后舵机暂时不响应，通信恢复后突然转向大角度目标；
- 舵机离线期间CH1目标仍在累积，最终可达`-100°`；
- 机械限位堵转后，旧程序只显示状态，不会锁存停机；
- 断开DAPLink后控制失效，怀疑主板供电或共地依赖DAPLink。

## 2. 核心原因

1. FSUS回读为阻塞式交易，原超时为`100 ms`，连续超时会卡住`20 ms`控制循环。
2. 运动命令与ServoMonitor查询可能背靠背发送，不满足厂家建议的`5~10 ms`命令间隔。
3. USART2单字节中断接收重新挂载失败后，旧程序只计数，不会任务级自愈。
4. `BSP_UART_Fsus_Send()`旧接口无返回值，HAL发送失败仍可能显示`wr=0`。
5. 运动命令默认无ACK；一帧丢失后，旧程序可能把本地状态误认为已执行。
6. 反馈断开期间RC积分器仍运行，重连后会立即执行隐藏的累积目标。
7. RTT强制角度模式原本绕过反馈新鲜度和堵转保护。
8. HX8状态位解析错误：`BIT0`仅表示指令执行中，不应当作过载错误。

## 3. 通信层修复

- FSUS单次回读超时由`100 ms`缩短至`20 ms`。
- 在唯一FSUS发送入口增加`5 ms`最小帧间隔。
- FSUS发送接口改为返回`AraStatus_t`，新增`FSUS_PARSE_TX_FAILED`。
- 增加USART2 RX任务级自愈：每次Ping/Monitor前检查中断接收是否真正挂载，异常时主动Abort并重新挂载。
- 增加USART2错误计数：TX失败、RX错误、RX重挂失败、环形缓冲区溢出和最后HAL错误位。
- 运动目标每`200 ms`低频重发，降低默认无ACK模式下单帧丢失的影响。
- 扭矩/故障状态下每`200 ms`重复发送幂等Stop/Unlock，链路恢复后可再次收到停止命令。
- Stop帧发送失败时不再把软件状态标记为已停止，下一控制周期继续重试。

## 4. 控制与重连安全

- 计算真实物理反馈年龄，不再把缓存位置当作新回包。
- 一个完整`100 ms`反馈周期内未获得新帧，立即使运动命令失效。
- 舵机离线时每个周期都用最后一次真实编码器位置覆盖CH1积分目标。
- HX8重新上线时，使用当前编码器位置初始化RC和操作器保持目标。
- 要求CH1连续居中`300 ms`后才重新允许手动运动。
- 修复启动/AUTO无视觉时操作器历史目标回退到`0°`的问题。
- RTT强制角度模式现在同样受反馈新鲜度与堵转保护限制。

## 5. 堵转与编码器诊断

- 按协议重新解析HX8状态：
  - `BIT0`：指令执行中；
  - `BIT2`：堵转；
  - `BIT1~BIT7`：错误/保护位。
- 新鲜回包出现`BIT2`时锁存`SERVO_STALL`，立即请求Stop/Unlock，并屏蔽ELRS、视觉和RTT运动命令。
- 堵转解除后仍保持故障锁存，需要CH1回中并执行人工复位。
- 增加新鲜编码器帧连续性检查，统计物理不可能的角度跳变。
- 编码器无跳变但机械臂角度偏移时，优先检查外部`40:48`齿轮、舵盘和连杆是否打滑/跳齿。

## 6. 手动模式临时安全参数

| 参数 | 修复前 | 修复后 |
| --- | ---: | ---: |
| HX8手动速度 | 750°/s | 300°/s |
| 加速时间 | 50 ms | 120 ms |
| 减速时间 | 50 ms | 120 ms |
| CH1目标积分速度 | 500°/s | 240°/s |

说明：降速用于故障排查阶段限制机械后果，不是将通信问题简化为速度问题。通信和供电通过真机验收后，可逐步提高至480°/s并重新测试。

## 7. RTT新增可观测信息

```text
[SAFE] ch1=0 fb_age=20 ms reconnect_guard=0 stall=0 encoder_jumps=0
[BUS] txe=0 rxe=0 rearm=0 overflow=0 hal=0x0
```

- `txe`：STM32 USART2发送失败数；
- `rxe`：USART2接收错误数；
- `rearm`：RX中断重新挂载失败数；
- `overflow`：FSUS RX环形缓冲区溢出数；
- `hal`：最后一次HAL UART错误位；
- `fb_age`：最后一次真实HX8监控回包的年龄；
- `encoder_jumps`：疑似编码器不连续计数。

## 8. TOFSense-F2 P调试支持

- 增加RTT命令`i`，只读检测I²C地址`0x08`的TOFSense-F2 P寄存器数据。
- 增加`TOFSENSE_SAFE_TEST`独立构建模式，测距时不启动主臂控制任务和PTK PWM。
- 增加`tools/tofsense_live_rtt.ps1`，用于通过RTT临时显示实时距离。

## 9. 构建验证

- 正常固件干净重建通过；
- TOFSense安全测试固件构建通过；
- 额外使用`-Wall -Wextra -Wshadow`进行严格编译检查；
- 正常固件资源占用：Flash约71.6%，RAM约72.5%。

## 10. 尚未完成的真机验收

当前DAPLink未连接，新固件尚未烧录。不能仅凭静态代码审查宣称物理通信已彻底稳定。

烧录后建议以300°/s连续测试至少2分钟，验收标准：

- `rd` 持续为`0`；
- `fb_age` 在`0~80 ms`内循环，不达到`100 ms`；
- `txe/rxe/rearm/overflow` 全部保持`0`；
- `stall=0`、`encoder_jumps=0`；
- 不再出现通信恢复后突然执行`-100°`。

如断开DAPLink后实际ELRS控制仍失效，需要检查主板独立`3.3 V`供电、`NRST/BOOT0`电平，以及STM32、ELRS、UC-01、HX8电源是否可靠共地。

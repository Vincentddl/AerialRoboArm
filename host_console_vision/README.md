# 机载机械臂实验上位机（Windows）

本上位机配合 HC13 V2 实验固件。正常位和折叠位由校准模式保存，以 `runtime/pose_calibration.json` 的当前数值为准；手动出臂角度始终相对已保存的正常位换算，因此从两种位置起步会到达同一绝对目标。设备 INFO 回报速度上限，模式一手动速度控件上限为 78%；视觉抓取页面有独立速度控件。角度和速度仍须以当前机械安装状态实物验证。

手动“按当前参数抓取”与视觉抓取使用 MCU `PICK`：发送时锁定目标、速度与默认 4°提前量；MCU 根据 HX8 的新鲜实际位置，在目标前应用一次夹爪闭合 PWM 90°，HX8 继续到目标。收到 `PICK DONE` 和新鲜、无故障的空闲状态后，手动抓取以 INFO 速度上限的 10% 返回当前校准的折叠位，视觉抓取仍以 60% 返回本次起点，保持闭爪。普通“启动出臂”使用 `MOVE`，不自动闭爪。夹爪没有位置或夹持反馈，`CLOSE_APPLIED` 不代表抓取成功。

回位后取得新鲜的空闲位置反馈，手动页才允许再次按“按当前参数抓取”。若上次抓取后夹爪仍是闭合 PWM，上位机先在 HX8 空闲时发送张开 PWM，收到 `SERVO:APPLIED` 后立即用本次点击时的速度和角度发送 `PICK`；夹爪的物理张开可与前伸重叠，但没有开到位反馈。开爪被拒绝时不出臂。再次抓取仍返回折叠位。固件运动中拒绝独立 SERVO，所以不会在已开始的运动里补发开爪指令。

正常／归零先以 60% 速度移动 HX8 至 +90°，再应用张开 PWM 125°；折叠先应用张开 PWM 125°，再以 40% 速度移动至 +160°。两处角度均为安装偏差调整后的临时试验值，机构边界待实测。MCU 原生 `HOME/PREP/SHAPE` 的等待及折叠标定仍可能是 `NA`；这些 PC 工作预设通过独立的 `MOVE/SERVO/PICK` 路径执行。

HX8 有效 `STATE.voltage_mv` 连续至少 2 秒、至少 3 条均低于 10.60 V 时，上位机报警并锁定操作。若有动作或待确认控制请求，程序发送优先 STOP，并暂停自动采集。关掉弹窗或断线后锁定仍有效。通信恢复后，新鲜电压反馈达到 10.80 V 才解锁，批次由操作者手动继续。这个电压来自 HX8，换电时请以电池实测为准。

高速动作曾在运动开始约 0.15 秒、距离目标很远时报告 `FEEDBACK_STALE`。实验固件将运动中的短时 HX8 反馈缺帧宽限设为 400 ms，新动作准入仍需小于 200 ms 的健康反馈，持续异常仍中止。上位机仅在普通 `MOVE` 接近目标且新鲜位置连续稳定时使用 STOP 保持，不把远处卡住当作到位，也不自动清除故障。高速改善情况须用实物复测。

连接串口后必须收到有效 V2 `INFO/CAL/STATE` 和在线反馈才允许运动。第四个“实验模式”要求固件回报 `EXPERIMENT` 能力，通过 `XMOVE` 出臂并保存 JSON。信号测试还需要板载高频采样能力，并按所选轮次运行完整的行程、速度及加减速矩阵。已经使用板载高频采样固件的设备无需为此重新烧录。详见[实验模式说明](实验模式说明.md)。模拟数据不会混入真实曲线。

## 启动

在这台电脑上，双击 **`机载机械臂上位机.lnk`**。快捷方式直接调用已安装的 Python 3.11 和本项目的 `vendor/` 依赖，不需要再安装环境。若启动异常，本目录会生成 `startup_error.log`。

当前 Windows 的 `.bat` 文件关联异常，双击 `start_windows.bat` 会弹出“选择打开方式”；请使用上述快捷方式。也可在本目录的 PowerShell 中执行：

```powershell
python main.py
```

在其他电脑上，需要 Windows、Python 3.11+。在本目录打开 PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

`start_windows.bat` 在 `.bat` 文件关联正常的电脑上可用。它优先使用已装依赖的 `.venv`，否则使用系统 Python。本机开发环境已把依赖安装在 `vendor/`，程序入口会自动读取它；其他电脑应按以上步骤创建虚拟环境并安装依赖。`机载机械臂上位机.lnk` 含本机绝对路径，移动项目或换电脑后应重新创建快捷方式。

运行验收：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

若使用本机的 `vendor/`，可用 `python -m unittest discover -s tests -v`。

## 使用

1. 选择 COM 口并核对两块 HC13 实际波特率；界面默认 230400、8N1、无流控，打开端口前关闭 DTR/RTS，与实测能接收 ACC 的 XCOM 配置一致。连接后自动 `GET INFO`、`GET CAL`、`GET STATE` 并每秒 `PING`。串口打开不代表设备在线。
2. `AerialRoboArm` 的 **HC13 专用构建** 在 MANUAL、VISION_DEMO 下提供约 20 Hz 的 ACC 显示流；VISION_PICK 停发无线 ACC，但 MCU 内部仍采样 IMU。没有真实曲线时先检查是否收到 V2 INFO/STATE 与 ACC，不能单凭串口打开判断传感器状态。VISION_PICK 页面仍处理控制回执。
3. 左侧“正常模式”使用绝对 +90°工作位，以 INFO 最大速度的 60% 运行 HX8，到位后发送夹爪张开 PWM 125°。“折叠位置”先发送夹爪张开 PWM 125°，收到 ACK 后以 INFO 最大速度的 40% 移至暂定绝对 +160°。两处的开爪指令均只有 PWM 应用回执，没有夹爪位置反馈。物理标定零点仍是 0°。
4. “按当前参数抓取”可从正常位或折叠位起步，抓取后均返回当前校准的折叠位，回程速度为 INFO 最大速度的 10%。视觉抓取仍返回本次起点，回程速度为 60%。出臂绝对目标按当前保存的正常位与所填相对角度换算；回程前要求 `PICK DONE` 及随后新鲜、无故障的空闲反馈。
5. 手动页“归零”与正常模式使用相同的 +90°工作位、60% HX8 速度及到位后张开夹爪流程。设备协议中的 `SHAPE,NORMAL`／`SHAPE,FOLDED` 未删除，但左侧按钮不调用它们。只切换视觉页面不会发运动命令。模式 1 视频只显示原图上的中心竖线和五段标识，不显示 ROI 限制或识别结果。
6. 手动滑块的“出臂角度”是从 +90°工作位开始的相对行程，当前上位机限制为 0～70°；目标按 `90° - 出臂角度` 换算。启动前要求新鲜 HX8 实际位置在 `+90°` 或 `+160°` 的 ±5°内。“启动出臂”发送独立 MOVE，不自动闭爪。手动页同时显示 STATE 中的目标角度、实际角度和误差。手动夹爪按钮的 PWM 测试值为张开 125°、闭合 90°，夹爪没有实际位置反馈。
7. 视觉演示页使用 OpenCV 在中央 50% 区域搜索并跟踪单个黑块，显示红色对齐标注，不提交机械臂命令。视觉抓取页需要用户点击启动，目标中心连续处于同一五分区一定帧数后提交单次 `PICK`；两页共用视频采集。`CLOSE_APPLIED` 仅表示闭爪命令已应用，不能说明抓取成功。
8. STOP 和离开视觉抓取页面会取消后续决策并请求 MCU 中止待闭爪触发；已经下发的夹爪命令保持。实物停止效果和时序尚需测试。

### HC13 无响应排查

关闭上位机及 VOFA 等串口软件后，在本目录 PowerShell 中运行只读探测：

```powershell
python tools/probe_hc13_readonly.py --port COM4 --baud 230400
```

脚本先被动接收 2 秒，再只发送 `GET INFO`、`GET CAL`、`GET STATE`、`PING`；不会发送运动、夹爪或模式命令。原始收发字节、请求序号、电脑时间和解析结果写入 `diagnostics/hc13_probe_*.jsonl`。更换实际端口号再运行。**同一时刻只能由一个程序打开 COM 口**。上位机日志也显示每次实际串口写出的原始字节、序号和返回的非 ACC 原始帧；“已入队”不同于“实际写出”，两者都不代表 MCU 已接受。

若收到裸 `ERROR\r\n`，它不是 V2 的 `ERR,<id>,<code>`，不能当作 MCU 拒绝。2026-10-31 实测：原程序默认开启 DTR/RTS 时只收到裸 `ERROR`；关闭 DTR/RTS 后，同一 COM4 收到 ACC 及匹配请求号的 INFO/CAL/STATE/PONG，上位机已识别 V2 在线。若复测失败，再核对 COM 口、KEY、波特率、无线配置和机载镜像。[机载项目 HC13 配置](../AerialRoboArm/AerialRoboArm/Doc/hardware/hc13_config.md)给出的项目目标为 C043、S7，3.3 V 供电且建议电源能提供至少 300 mA；这些参数仍需对实物查询或测量。当前固件回报后折位置与开闭爪等待时间为 `NA`，相关动作仍受标定门控。详细证据见 [`docs/HC13_LINK_DIAGNOSIS_20261031.md`](docs/HC13_LINK_DIAGNOSIS_20261031.md)。

## 真实无线图传

1. 把图传接收设备接到电脑，先关闭 OBS Studio 或其他正在使用它的相机软件。在任一工作页面点击视频设备“刷新”。下拉框由 DirectShow 枚举，显示设备名、索引及设备路径摘要；只有**唯一**的 `USB Video` 会自动选中。若同名设备有多个，请依据路径和索引手动选取，不会默认打开内置摄像头。
2. 点击“打开视频”。程序用 OpenCV `VideoCapture(所选索引, CAP_DSHOW)`，保留设备默认分辨率、帧率及视频格式；连续取得三张有效帧后才显示“采集中”。画面状态展示实际帧尺寸与按电脑读帧时间统计的帧率。电脑端单调接收时间不是摄像头曝光时间。
3. 三个工作页面共用同一采集线程。手动页显示无识别叠加的原始图传预览，切页不会重开摄像头；小窗口可滚动查看手动控件和画面。真实画面按原始宽高比完整显示，不做镜像。视觉演示页在原图水平中央 50%（x 为 W/4～3W/4、纵向全高）搜索和跟踪黑块；局部跟踪窗口会裁剪到该范围。画面叠加方框、中心与原图坐标；视觉抓取页使用检测结果决定五分区候选，但仅在点击“启动”且连续稳定后提交一次抓取。模拟演示与真实视频互斥，开启模拟会关闭真实设备。
4. 点击“关闭视频”后旧画面立即清空，设备释放完成后可再次打开。持续失帧或拔出设备会显示异常并清除旧画面。若打开失败，查看底部日志并确认设备未被 OBS 占用。

`arm_console/video_capture.py` 定义 `VideoFrame(image, frame_id, received_monotonic_s, width, height)` 作为后续视觉算法输入。采集线程持有 OpenCV 对象；主线程每 33 ms 最多读取一张最新帧，长期运行不会堆积 Qt 的逐帧事件。

### 视觉演示黑色物块标注

进入侧边栏第二项“视觉演示模式”，选择并打开 `USB Video`，无需连接串口。SEARCH 和 TRACK 都严格限制在原始画面水平中央 50% 区域；TRACK 在 ROI 内的锁定目标附近关联后续帧，不被远处更大的黑块抢占。目标越过青色边界或轮廓被边界截断时按漏检处理，连续 20 个有效视频帧漏检后释放锁定，下一帧恢复中央区域搜索。青色虚线标出 ROI 边界，橙色竖线标出画面中心，紫色竖线标出目标轮廓视觉重心。画面显示单个方框、中心点和原图像素坐标及轮廓面积。

普通方框为青绿色；视觉重心进入画面中心线容差或连续两帧跨过中心线时，方框变红。红框状态持续到目标黑色连通区域完全离开中心线。暂时漏检时清除本帧框和坐标，页面显示连续漏检帧数；目标切换、失锁或关闭视频时清除旧红色状态。页面调整黑色阈值、最小面积、最大面积占比及对齐容差后，下一批帧立即使用新参数。此版本没有测距标定或掩膜诊断入口，也不会因识别结果发送机械臂命令。

| 真实图传采集 | `arm_console/video_capture.py`、`window.py` | DirectShow 按名称及路径枚举，按对应索引打开；单线程采集、单帧缓存、主线程分发至当前视觉页。 |

| 曲线显示 | `arm_console/plots.py` | 有界 6000 条缓存、20 Hz 绘图更新、5/10/30 秒窗口；原始三轴不滤波、不去重力、不翻转符号。 |
